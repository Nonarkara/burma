13 October 2026 · Targeted static review and local integration · Yellow: public alpha, not a security certification.

The security changes begun in this conversation are now tracked in commit `4d9ae71`; frontend follow-through is tracked in `a3c14bc`. This round verifies that foundation and adds contribution-draft checks. Confidence is high for the tested behaviours below, limited for the overall system. This is not a comprehensive pentest or a production load test.

## 1. Secrets

## 6. Request and browser controls

Verified controls:

- Streamed JSON/multipart byte limits precede parsing; understated or missing Content-Length cannot bypass the shared bounded reader.
- Upload limiter fails closed on unavailable storage; counters are transactional, expire, and do not retain the literal network address as a key. SHA-256 keys are not a promise of anonymity.
- Declared image MIME must match a supported signature; SVG and disguised HTML are rejected. This is not full image decoding, malware scanning or metadata stripping.
- Browser origins are restricted; malformed CDN paths are rejected. Origin checks do not authenticate command-line clients.
- Pin coordinates and note lengths are checked. Pin/watch mutations share a room budget; large socket messages and room connection count are bounded.
- Watch create/read/stop use the actual room key; persistence and broadcast were tested locally.
- Preview requests reject IP literals, internal-name patterns, credentials and unusual ports, and check redirects. Unsafe preview images are omitted. Arbitrary-domain DNS rebinding remains unaddressed; hostname checks alone are not complete SSRF protection. See [OWASP SSRF guidance](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html).
- Static headers disable referrers, objects and unwanted form/base destinations. The partial CSP does not block arbitrary injected scripts.
- Rendering regression checks reject executable message HTML and unsafe preview-link schemes.
- Contribution drafts never send automatically, do not replace existing composer text, require source URLs for opportunities and disclose unverified status.

Outstanding priorities: authenticated moderator access and private reporting; retention/consent review of public chat and pins; schema-level pin room isolation (the legacy pin listing is global); durable room-abuse budgets across object restarts; connection cleanup/load tests; comprehensive dependency/SAST analysis; full CSP and preview egress policy. Public anonymous rooms permit nickname spoofing; they are not private support channels or verified-identity services.

Local integration passes two-client fan-out, persisted reload, room isolation, limit forwarding, empty-message rejection, SVG rejection, R2/CDN retrieval and clean socket close. These writes used the local Worker only. Browser testing exercised the community contribution form at 320px and language switching without a public test post.
